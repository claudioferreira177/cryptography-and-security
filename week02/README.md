# Week 2 — Classical Ciphers and One-Time Pad

## Overview

This week introduces fundamental cryptographic concepts through the implementation and analysis of the Caesar cipher, the Vigenère cipher, and the One-Time Pad (OTP).

Besides implementing encryption and decryption, the exercises demonstrate how limited key spaces, letter-frequency analysis, and insecure pseudo-random key generation can compromise a cryptographic system.

## Implemented Programs

| File | Description |
|---|---|
| `cesar.py` | Encrypts and decrypts text using the Caesar cipher. |
| `cesar_attack.py` | Tries every possible Caesar key and identifies plaintext using known words. |
| `vigenere.py` | Encrypts and decrypts text using the Vigenère cipher. |
| `vigenere_attack.py` | Recovers a Vigenère key of known length using letter-frequency analysis and known words. |
| `otp.py` | Implements binary OTP encryption and decryption with keys generated by `os.urandom`. |
| `my_otp.py` | Replaces the secure key generator with a deliberately vulnerable pseudo-random generator. |
| `my_otp_attack.py` | Recovers plaintext by exhaustively testing the vulnerable generator's `2^16` possible seeds. |

## Requirements

- Python 3.9 or later
- No external dependencies

## Usage

### Caesar Cipher

```bash
python3 cesar.py enc G "CartagoEstaNoPapo"
python3 cesar.py dec G "IGXZGMUKYZGTUVGVU"
python3 cesar_attack.py "IGXZGMUKYZGTUVGVU" BACO PAPO
```

### Vigenère Cipher

```bash
python3 vigenere.py enc BACO "CifraIndecifravel"
python3 vigenere.py dec BACO "DIHFBIPRFCKTSAXSM"
python3 vigenere_attack.py 3 "PGRGARHSFHPRGCVHOJHWEPZRSCJFIVSOFRWUTBKPZGGOZPZLHWKPBR" PAPO PRAIA
```

### One-Time Pad

```bash
python3 otp.py setup 30 otp.key
python3 otp.py enc message.txt otp.key
python3 otp.py dec message.txt.enc otp.key
```

The decrypted message is written to `message.txt.enc.dec`.

### Vulnerable Key Generator

```bash
python3 my_otp.py setup 30 weak.key
python3 my_otp.py enc message.txt weak.key
python3 my_otp_attack.py message.txt.enc known words
```

The attack tests every possible seed and prints the first plaintext containing one of the supplied words.

## Security Analysis

### Q1 — Is there any difference between `otp.py` and `my_otp.py`?

The programs have the same external behaviour: both generate a key, encrypt with XOR, and decrypt by applying XOR again. The critical difference is how the key is generated.

`otp.py` uses `os.urandom`, which provides random bytes suitable for cryptographic use. In contrast, `my_otp.py` seeds Python's deterministic `random` module through a deliberately weak seed-expansion function. Although the initial seed contains 16 random bytes, the expansion reduces the effective seed space to only `2^16` possibilities.

Consequently, the vulnerable generator can produce only 65,536 possible key streams, making exhaustive search practical.

### Q2 — Does the attack contradict the perfect secrecy of the One-Time Pad?

No. Perfect secrecy applies only when the OTP key is uniformly random, at least as long as the message, independent of the plaintext, kept secret, and used only once.

The vulnerable implementation violates the randomness requirement. Its key is produced by a predictable generator with a small effective seed space, allowing an attacker to regenerate every possible key stream and identify plausible plaintext using known words.

The attack therefore does not break the One-Time Pad itself. It breaks the insecure key-generation process on which this particular implementation depends.

## Key Takeaway

The security of a cryptographic system depends not only on the encryption operation, but also on how its keys are generated. A theoretically secure construction such as the One-Time Pad becomes vulnerable when supplied with predictable key material.
